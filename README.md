# mywotb

Легкий локальний макет сайту для статистики та сесій гравця **World of Tanks Blitz**, регіон **EU**.

## Запуск

Залежностей немає — потрібен лише Node.js 18+:

```bash
node --run dev      # або: node server.js
```

Відкрийте **http://localhost:8081**. Порт можна перевизначити: `PORT=8082 node server.js`.

## Що є

- **Профіль:** пошук гравця, три метрики (кількість боїв, відсоток перемог із двома знаками після коми, середня шкода), список техніки. WN7 / WN8 / WTR не використовуються. Шрифти — звичайні `Arial / Helvetica`.
- **Техніка:** сортування по кожному стовпцю. Замість тексту класів — значки: легкий — ромб, середній — дві діагональні риски, важкий — три, ПТ-САУ — перевернутий трикутник, САУ — приціл.
- **Сесії:** безперервні — є лише кнопка «Завершити поточну сесію», після неї одразу стартує нова; таймера немає. Нотатка й історія лишились. Сесія рахує **кожен танк окремо** і додає рядок **«Загалом»** у межах однієї сесії. Колонки лише: **Боїв**, **Вінрейт / % перемог**, **Середня шкода**, **Виживання**. Решта метрик із сесій прибрана.

## Відмітки на стволі (Gun Marks)

Офіційні пороги є: 1 відмітка — топ **35%**, 2 — топ **15%**, 3 — топ **5%** гравців за середнім Gun Mark XP за останні 50 боїв (мінімум 5 000 боїв, лише Random Battles). Але точні числа по кожній машині Wargaming через API не віддає — вони є лише на сторонніх сайтах (наприклад, BlitzInfo) як оцінка. У макеті показані офіційні відсоткові пороги.

## PWA

Є `manifest.webmanifest`, іконки 180/192/512 у `icons/`, service worker `sw.js` (app-shell, без кешування API). У хедері з'являється кнопка встановлення, коли браузер сам підтримує `beforeinstallprompt`.

## Синхронізація через Supabase

Використано ті самі проєкт/anon-ключ і таблицю `user_library`, що й у **mycinema-web** (окрему таблицю створювати не треба):

- авторизація email/пароль через `@supabase/supabase-js@2` (динамічний імпорт із CDN; без мережі працює локальний режим);
- сесії зберігаються рядками з `item_key = wotb.session.<id>`, активна сесія — `wotb.active`;
- при вході дані з хмари зливаються з локальними, після змін — debounced upsert;
- кнопка «Увійти» у хедері відкриває модальне вікно входу/реєстрації/виходу та ручного «Синхронізувати».

Якщо в таблиці вашого Supabase інша схема — синхронізація покаже помилку в тості, локальні сесії при цьому не втрачаються.
